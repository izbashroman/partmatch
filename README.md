# PartMatch — автоматичне зведення прайсів постачальників з каталогом

Що тут є:
- `parser/` — Python-скрипт, що тягне каталог + прайси постачальників з Google
  Sheets, зіставляє і формує `report.csv` / `unmatched_supplier_offers.csv`
- `docs/index.html` — веб-інтерфейс для перегляду/пошуку по цих звітах
  (працює як статична сторінка — GitHub Pages)
- `.github/workflows/update.yml` — робота, що щодня (за розкладом) сама
  запускає парсер і кладе свіжі CSV у `docs/`, а сторінка їх сама підхоплює

Результат: заходите на сторінку — і там уже свіжі дані, без ручного
завантаження файлів.

## Встановлення (один раз)

1. **Створіть новий репозиторій на GitHub** (Private або Public — не
   принципово, дані не секретні, окрім факту, що видно ваші прайси).

2. **Завантажте туди вміст цього архіву** — простіше через веб-інтерфейс
   GitHub (Add file → Upload files, перетягнути все, крім `.git`, якщо він
   був), або через git у терміналі:
   ```bash
   cd шлях/до/розпакованого/архіву
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГІН/ВАШ_РЕПО.git
   git push -u origin main
   ```

3. **Дозвольте Actions писати в репозиторій:**
   Settings → Actions → General → Workflow permissions →
   **"Read and write permissions"** → Save.
   (Без цього кроку робота зможе рахувати звіт, але не зможе закомітити
   результат назад.)

4. **Увімкніть GitHub Pages:**
   Settings → Pages → Source: **Deploy from a branch** → Branch: **main**,
   папка **/docs** → Save.
   Через хвилину-дві сторінка буде доступна за адресою на кшталт
   `https://ВАШ_ЛОГІН.github.io/ВАШ_РЕПО/`.

5. **Запустіть перший прогін вручну** (не чекаючи розкладу):
   вкладка **Actions** → зліва "Update price match report" →
   праворуч кнопка **Run workflow** → Run workflow.
   Через 1-2 хвилини в `docs/` з'являться `report.csv` і
   `unmatched_supplier_offers.csv`, і сторінка Pages почне їх показувати
   автоматично при відкритті.

Після цього все відбувається саме: щодня о 06:00 UTC (налаштовується —
дивіться нижче) робота сама перезбирає звіт і комітить оновлені CSV.
Відкриваєте сторінку — там завжди свіжі дані, ручне завантаження CSV більше
не потрібне (хоча drag&drop нікуди не подівся — можна й далі підвантажувати
файли вручну, якщо треба глянути щось окреме).

## Як змінити розклад

У файлі `.github/workflows/update.yml` рядок:
```yaml
- cron: "0 6 * * *"
```
Формат cron: `хвилина година день місяць день-тижня`, час — завжди UTC.
Наприклад, `0 5,17 * * *` — двічі на день, о 5:00 і 17:00 UTC.
Можна скористатись https://crontab.guru для підбору виразу.

## Як додати нового постачальника

1. Напишіть парсер у `parser/parsers/новий_постачальник.py` (за зразком
   вже наявних — `parser/README.md` пояснює патерни: матрична таблиця
   Серія|Модель чи вільнотекстовий прайс).
2. Додайте запис у `parser/config.py` (`SUPPLIERS`) — sheet_id, gid,
   валюта, назва парсера.
3. Зареєструйте парсер у `PARSER_MAP` в `parser/main.py`.
4. Закомітьте — наступний запуск (за розкладом або вручну через
   Run workflow) підхопить його сам.

## Обмеження

- Google Sheets постачальників мають бути відкриті "для всіх, у кого є
  посилання" (перегляд) — інакше `export?format=csv` поверне помилку
  доступу і робота залоґує "ПОМИЛКА" по цьому джерелу, не зупиняючи решту.
- GitHub Actions за замовчуванням безкоштовний ліміт — 2000 хв/міс для
  приватних репо (для публічних — необмежено). Цей парсер займає
  секунди-хвилину на прогін, розкладу раз на день вистачить з великим
  запасом.
- Детальніше про сам парсер (структура, як усунено баги з розпізнаванням
  моделей/класів, як він працює) — дивіться `parser/README.md`.
