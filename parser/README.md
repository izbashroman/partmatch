# Парсер/матчер прайс-листів постачальників

Тягне прайси кількох постачальників (Google Sheets) + внутрішній каталог,
зіставляє позиції за (модель пристрою, клас деталі) і показує, у кого
є потрібна деталь і по якій ціні.

## Запуск

```bash
pip install pandas requests
python3 main.py          # реальний прогін — тягне живі Google Sheets
python3 test_run.py      # офлайн-демо на sample_data/, без мережі
```

Результат: `output/report.csv` (по кожній позиції каталогу — найкраща ціна
і повний список пропозицій постачальників) та
`output/unmatched_supplier_offers.csv` (позиції постачальників, яким не
знайшлось відповідника в каталозі — кандидати на розширення мапи класів
або нові позиції каталогу).

**Важливо:** з цього пісочного середовища (де я зараз пишу код) немає
мережевого доступу до docs.google.com, тому `main.py` я не можу прогнати
наживо звідси. Пайплайн повністю перевірений офлайн (`test_run.py`) на
реальних фрагментах даних з ваших таблиць — парсери, нормалізація і
матчинг працюють. Запустіть `main.py` на своїй машині (або дайте мені
знати, якщо захочете, щоб я спробував ще раз через web-інструменти) —
логіка та сама, різниця лише в джерелі CSV.

## Структура

```
config.py        — реєстр джерел (ID таблиць, gid вкладок, валюта)
fetch.py         — завантаження вкладки Google Sheets як CSV
normalize.py     — нормалізація моделі пристрою (iPhone/Galaxy/AirPods/MacBook)
                    і класу деталі (АКБ/дисплей/корпус/...)
parsers/
  catalog.py     — парсер внутрішнього каталогу (Geckon)
  icracked.py    — матричний парсер (Серія|Модель|кілька цінових колонок)
  levelparts.py  — той самий підхід, простіша таблиця
  freetext.py    — спільна логіка для "назва товару вільним текстом + ціна"
  ocapro.py      — обгортка freetext під OCAPRO
  refparts.py    — обгортка freetext під REFparts
  uparts.py      — обгортка freetext під UParts (без прив'язки до моделі)
match.py         — зведення каталогу з пропозиціями, конвертація UAH->USD
main.py          — реальний запуск (мережа)
test_run.py      — офлайн-демо (sample_data/)
```

## Що вже підключено

| Постачальник | Формат | Покриття в парсері |
|---|---|---|
| iCracked | матриця Серія/Модель, кілька варіантів АКБ | АКБ iPhone (обидва блоки на вкладці) |
| OCAPRO | вільний текст + 2 ціни (роздріб/опт) | AirPods, Galaxy (OCA, АКБ, дисплеї, корпуса) |
| REFparts | вільний текст + 3 рівні опту | Скло/OCA, рамки, плівки iPhone |
| "Price" (@levelpart_s) | матриця Серія/Модель | Корпуса/скло корпусу iPhone |
| UParts b2b | вільний текст, без моделі пристрою | Витратні матеріали, інструменти |

**Не підключено:** "PRICE SKLO Repair" (посилання не віддає дані — потрібен
робочий доступ) і додаткові вкладки iCracked (LCD дисплеї, корпуса, тач/скло,
шлейф — та сама книга, інші gid, поки не підтверджені).

## Обмеження й що варто перевірити перед довірою до цифр

1. **Класифікація "Клас" для iCracked та Levelparts — евристична.**
   Наприклад, я маплю "Банка Стандарт" → "АКБ без калібрування", а
   "Genuine" → "АКБ з калібруванням" — це не точна відповідність, а
   найближче за змістом. Варто звірити кілька рядків вручну і поправити
   `COLUMN_KLAS_KEYWORDS` у відповідному парсері.
2. **Розпізнавання моделі Galaxy/AirPods/MacBook — мінімальний список**
   у `normalize.py` (`GALAXY_MODELS`, `AIRPODS_MODELS`, `MACBOOK_MODELS`).
   Розширювати за потреби — просто додати рядок у список.
3. **Курс UAH→USD** — константа `UAH_TO_USD_RATE` у `config.py`,
   потрібно оновлювати вручну (або підключити live-курс пізніше).
4. **Каталог у прикладі — лише 12 позицій** (ті, що ви присилали раніше).
   Реальний каталог, за вашими даними, ~329 класів — при першому реальному
   запуску очікуйте на порядок більше збігів і, ймовірно, кілька нових
   випадків, які знадобиться додати в `PART_CLASS_RULES`/`COLUMN_KLAS_KEYWORDS`.

## Додати нового постачальника

1. Якщо формат "матриця Серія|Модель + кілька цінових колонок" — скопіюйте
   `levelparts.py`, поправте `COLUMN_KLAS_KEYWORDS`.
2. Якщо формат "назва товару вільним текстом + 1-3 ціни" — новий файл
   на 10 рядків типу `ocapro.py`, що викликає `freetext.parse(...)`.
3. Додайте запис у `config.py` (`SUPPLIERS`), додайте парсер у
   `PARSER_MAP` в `main.py`.
